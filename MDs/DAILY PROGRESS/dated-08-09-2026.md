## 1. System Status & Readiness Overview

The RTMP Live-Streaming and VOD platform has been upgraded to a resilient dual-layer ingest architecture to solve DJI drone connection drops and ensure a single continuous flight recording:

1. **Dedicated Ingest Relay (`rtmp-nginx-rtmp` on Port 1935):**
   - Utilizes `alfg/nginx-rtmp:latest` with built-in FFmpeg.
   - Buffers raw RTMP connections from DJI RS 2 remote controller and OBS Studio.
   - Eliminates the strict MediaMTX error (`closed: received a packet for video track 0, but track is not set up`).
   - Automatically relays accepted streams to MediaMTX via RTSP TCP (`rtsp://mediamtx:8554/live/$name`) with valid SPS/PPS metadata headers.

2. **Single Continuous Recording Guarantee:**
   - Configured `ping 10s; ping_timeout 5s; drop_idle_publisher 10s;` to tolerate cellular handovers and momentary packet pauses without dropping the session.
   - `recordSegmentDuration: 6h` in MediaMTX ensures the flight writes to one single MP4 file.
   - Set 500KB minimum filter in VOD sync logic to prevent aborted connection tests from cluttering the library.

3. **Real-Time Live Status Tracking:**
   - Implemented dual-layer live status detection (`activePublishers` in memory + MediaMTX `/v3/paths/list`).
   - Dashboard stream card immediately displays the pulsing red **LIVE** badge upon stream connection.

4. **Brand Asset:**
   - Custom high-resolution Dhanush UAV drone quadcopter SVG favicon added to `client/public/favicon.svg` and linked in `index.html`.
