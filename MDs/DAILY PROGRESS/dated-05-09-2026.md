## 1. Issues Investigated

### OBS Studio Stream Broken — Video Not Displaying on Webpage (CRITICAL)

**User Report:** After the 04-09-2026 changes, OBS Studio streaming (previously working perfectly) stopped showing video on the web player. Dashboard showed the stream as "live" but video player was black.

**Root Cause — Two Compounding Issues:**

1. **OBS RTMP URL Changed to `/ingest` by Mistake:**
   - On 04-09-2026, the DJI drone resolution-normalization feature changed all dashboard RTMP URLs from `rtmp://rtmp.dhanushuav.in:1935/live/{key}` to `rtmp://rtmp.dhanushuav.in:1935/ingest/{key}`.
   - OBS (which needs no transcoding) was now pushing to the `ingest/*` path instead of directly to `live/*`.

2. **FFmpeg Transcoding Command Used Bash-Only Syntax:**
   - The `mediamtx.yml` `runOnReady` command used `${MTX_PATH/ingest/live}` — a bash parameter substitution syntax.
   - The `bluenviron/mediamtx:latest-ffmpeg` Docker image is based on **Alpine Linux** with `/bin/sh` (busybox ash), which does NOT support `${var/find/replace}`.
   - FFmpeg failed to start or published to the wrong path, so **nothing appeared on the `live/*` path** for the web player.
   - The dashboard showed "live" because `getLiveStreamsFromMediaMTX()` strips both `live/` and `ingest/` prefixes, detecting the stream on the `ingest/*` path.

**Combined Effect:** OBS → `ingest/{key}` → FFmpeg silently fails → `live/{key}` empty → HLS player has no source → black video.

## 2. Actions Taken

### Fix: Separated OBS (Direct) and Drone (Transcoded) Paths

**Architecture Design Decision:**
- **`/live/{key}`** = Direct publish path for OBS Studio and standard sources (no transcoding, lowest latency)
- **`/ingest/{key}`** = Auto-transcoding path for DJI drones only (normalizes resolution to 1280×720)

**Files Modified:**

1. **`mediamtx/mediamtx.yml`** — Fixed `runOnReady` to use `sh`-compatible syntax:
   ```yaml
   runOnReady: >
     sh -c 'LIVE_PATH=$(echo $MTX_PATH | sed "s/ingest/live/");
     ffmpeg -i rtsp://localhost:8554/$MTX_PATH ... -f rtsp rtsp://localhost:8554/$LIVE_PATH'
   ```
   Updated comment to clarify `live/*` accepts both direct publishers AND transcoded drone output.

2. **`server/src/routes/streams.ts`** — Reverted all `obs_server` and `domain_rtmp` fields back to `/live`. Added new `drone_rtmp` field pointing to `/ingest/{key}` for future drone use.

3. **`client/src/components/StreamCard.tsx`** — Reverted fallback OBS server URL to `/live`.

4. **`client/src/pages/LivePlayer.tsx`** — Reverted fallback RTMP copy URL to `/live`.
