## 3. Root Cause Analysis: Why DJI GO 4 Showed "Connecting..."

Since the server and URL `rtmp://rtmp.dhanushuav.in:1935/live/73846` are verified working from the outside world, the failure is isolated to the **field mobile device / DJI GO 4 app environment**:

### 🔴 1. Mobile Phone Internet Routing While Connected to Drone
- **Phantom 4 Standard:** The phone connects to the remote controller via **Wi-Fi** (`PHANTOM4_XXXXXX`).
- When a phone joins a Wi-Fi network without internet, Android and iOS route **all** network packets (including RTMP) through Wi-Fi by default.
- The phone sends RTMP packets into the drone's remote controller, where they are discarded. The packets never leave through 4G/5G mobile data.
- **Fix:** On the mobile phone, turn on "Switch to mobile data" / "Mobile data always active" or use a dedicated mobile SIM / hotspot.

### 🔴 2. Cellular Carrier CGNAT Dropping Port 1935
- Indian mobile carriers (especially Reliance Jio and Airtel mobile) commonly block outbound **TCP port 1935** on mobile data SIM cards.
- The app sends TCP SYN packets that are silently dropped by the cell tower, leaving DJI GO 4 in a `SYN-SENT` hang ("Connecting...").
- **Fix:** Test if port 1935 is open on the field SIM using `http://portquiz.net:1935` in the mobile browser, or test with a mobile Wi-Fi hotspot from a different network operator.

### 🔴 3. DJI GO 4 Microphone Permission Denied
- DJI GO 4 requires access to the mobile device's microphone to encode the RTMP audio stream (since Phantom 4 has no onboard mic).
- If Microphone permission was denied in phone settings, the audio encoder halts and DJI GO 4 hangs on "Connecting..." indefinitely.
- **Fix:** Phone Settings → Apps → DJI GO 4 → Permissions → Enable **Microphone**.

### 🟡 4. Mobile Carrier DNS Failure for `rtmp.dhanushuav.in`
- Mobile carrier DNS servers occasionally fail to resolve newly registered or subdomains.
- **Fix:** Use the direct public IP in DJI GO 4:
  `rtmp://14.97.37.70:1935/live/73846`
